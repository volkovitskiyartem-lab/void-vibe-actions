# VOID VIBE — Public Actions Runner

Этот репозиторий запускает GitHub Actions на стандартных публичных GitHub-hosted runners. Код бота, состояние переноса музыки, история «Трека дня», данные Telegram и музыкальные аудиофайлы остаются в закрытом репозитории `volkovitskiyartem-lab/void-vibe-router`.

**Текущий режим: готовность к настройке, автоматические задачи не активированы.** Все шесть рабочих сценариев запускаются только при наличии repository variable `PUBLIC_RUNNER_ENABLED=true`. До завершения безопасного переключения эту переменную **не создавать / не включать**.

## Установленные сценарии

| Workflow | Назначение | Защита |
|---|---|---|
| `preflight.yml` | Ручная проверка секретов, доступа к private и тестов, без Telegram-публикаций | Нет scheduled trigger |
| `music.yml` | Сбор музыки и ежедневная порционная публикация по текущим правилам бота | `PUBLIC_RUNNER_ENABLED=true`, личная приватная ветка `router-state` |
| `daily.yml` | «Трек дня»: сбор кандидатов и выпуск | `PUBLIC_RUNNER_ENABLED=true`, приватная ветка `daily-state` |
| `dj-hour-draft.yml` | Пятничный часовой DJ-черновик | `PUBLIC_RUNNER_ENABLED=true`, аудио только в приватном draft Release |
| `dj-hour-approve.yml` | Утверждение прослушанного сета | `PUBLIC_RUNNER_ENABLED=true`, проверка исходного run, приватный draft Release |
| `dj-publish.yml` | Воскресный выпуск утверждённого сета с проверкой прав | `PUBLIC_RUNNER_ENABLED=true`, журнал в приватной ветке `dj-state` |
| `ci.yml` | Ночные/ручные тесты | `PUBLIC_RUNNER_ENABLED=true` |

В этом репозитории **нельзя** публиковать: Telegram StringSession, API hash, пароль, `data/`, `state/`, `router.sqlite3`, архивный каталог, исходные или смонтированные DJ-аудиофайлы, присланные треки, полные журналирующие данные из PRIVATE.

## Подготовка перед первым включением

1. В GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens создать токен **только для `volkovitskiyartem-lab/void-vibe-router`**, разрешение Repository Contents: **Read and write** (для обновления закрытых веток и сохранения приватных draft Releases); остальные разрешения оставить по минимуму. Токен не публиковать в Issue, PR или чате.
2. В репозитории **`void-vibe-actions`** открыть Settings → Secrets and variables → Actions → **Secrets** → New repository secret, добавить `PRIVATE_REPO_TOKEN`.
3. В ту же область добавить существующие или отдельно безопасно полученные Telegram secrets: `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`, `TG_DAILY_SESSION`, `TG_DJ_SESSION`. Опционально `TG_QUEUE_ALERT_CHAT_ID`. Значения GitHub ранее заданных секретов **нельзя получить обратно из интерфейса**; при необходимости настроить их повторно локально, но не через публичные коммиты.
4. На странице Actions вручную запустить **VOID VIBE public runner security preflight**. Она проверяет наличие секретов, закрытые ветки и основные тесты **без отправки сообщений в Telegram и без изменения состояний**.
5. После успешного preflight нужно выполнить ручную проверку сценариев и подготовить безопасный cutover. Сначала остановить прежние Private workflows с ожиданием полного сохранения прогресса (подготовленные guards находятся в закрытой ветке `migration/public-runner-safe-20261014`; в `main` они ещё не включены), затем в новом Public установить `PUBLIC_RUNNER_ENABLED=true` и перенести нужные флаги `ROUTER_PAUSED`, `MUSIC_TRANSFER_PAUSED`, `DAILY_TRACK_PAUSED`, `DJ_SETS_PAUSED`, `DJ_AUTOPUBLISH_ENABLED`, `DJ_RIGHTS_CONFIRMED`. Не включать автопубликацию сетов без подтверждённых прав и предусмотренного ручного прослушивания.
6. Проверить `music.yml` вручную в `mode=verify`, `daily.yml` в `mode=preview`; сверить приватные журналирующие данные и только затем подтвердить рабочие расписания. Не допускать параллельных публикаций из обоих репозиториев.

**Внимание:** у старого PRIVATE проекта остались дополнительные редкие workflows (например, модерация заголовка «Трека дня», архивное обслуживание, диагностические и аудио-экспортные задачи). Их запуски будут продолжать расходовать месячные минуты, пока не будут отдельно безопасно перенесены либо отключены. Основные шесть сценариев из таблицы подготовлены для Public.

## Безопасность

- Public runner исполняет только проверенный код из приватного `main`; он не запускает код из чужих Pull Requests. В Public `main` следует запретить непроверенные прямые изменения и давать доступ к Secrets только доверенному коду.
- Хранимые/полученные DJ MP3 не выгружаются в GitHub Actions artifacts публичного репозитория, а сохраняются как **draft Releases** в исходном Private-репозитории. Необходимо отдельно отслеживать их размер, сроки хранения, условия GitHub и права на распространение.
- Оригинальный `void-vibe-router` не переводить в Public: его история, закрытые рабочие ветки и старые артефакты могут содержать чувствительные данные.
- `GITHUB_TOKEN` в публичных workflows по умолчанию имеет `contents: read`; запись в закрытые ветки выполняется отдельно посредством репозиторно-ограниченного `PRIVATE_REPO_TOKEN`.

### Аварийный стоп и откат

Сначала `PUBLIC_RUNNER_ENABLED=false` (перестанут начинаться новые задания), затем дождаться завершения текущих jobs. Перед возвратом на Private нужно убедиться в сохранении последних квитанций и отсутствии параллельных запусков. Старые задачи не переключать назад, пока не подтверждена целостность журналов.

### Учёт расхода

Стандартные GitHub-hosted runners для **Public** репозитория не расходуют квоту 2 000 минут Private Actions. Отдельные лимиты и расходы могут относиться к хранилищу, внешним сервисам, Codex и платным runner-тарифам.
